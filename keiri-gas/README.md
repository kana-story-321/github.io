# 経理アシスタント（個人事業主向け・GAS）

お客様のGoogleアカウントの中だけで動く経理の自動化です。弊社はデータを持ちません。

- Gmailの領収書・請求書メールを集めて、電子帳簿保存法に沿って保存する（元メールeml・PDF・添付）
- 公式LINEに送られたレシートの写真・PDFを読み取って保存する（1枚に複数のレシートが写っていても分ける）
- カード明細を取り込んで領収書と突き合わせ、経費の仕分け（区分・勘定科目・事業割合）をAIが提案する
- 帳簿は年ごと、領収書は月ごとのフォルダに保存する。保存先の年は**取引日**で決める
- レシートの品目を1行ずつ読み、事業の品と個人の品が混ざっていれば、事業の品の分だけを経費の候補にする（台帳の「内訳」「事業の品の金額」、経費仕分けの「AIの事業分の金額」）
- 品目の合計と合計金額が合わないときは、読み間違いの可能性として「チェック」欄で知らせる

## 構成

```
📁 経理_（屋号）                    ← お客様のGoogleドライブ。弊社を「編集者」で共有してもらう
 ├ 📊 管理シート ＋ GAS（このコード）  ← メニュー「経理」はここに出る。年をまたいで使い続ける
 │    タブ：設定／年度一覧／仕分けルール／カード名（処理済み・対象リストは隠しタブ）
 ├ 📁 スキャン受付                   ← 紙の写真・ダウンロードしたPDF・LINEで届いたファイルの入口
 ├ 📁 カード明細受付                 ← カード明細（CSV・PDF・スクショ）の入口
 ├ 📁 2026年
 │   ├ 📊 2026年_帳簿                ← 領収書台帳／カード明細／カード突き合わせ／経費仕分け
 │   ├ 📁 01月 … 12月                ← 領収書の保存先（必要になったときに作る）
 │   └ 📁 控え                       ← 年を締めたときのCSV
 └ 📁 2027年 …
```

| 置き場所 | 中身 | 誰が入れるか |
|---|---|---|
| スクリプトプロパティ `GEMINI_API_KEY` | お客様ごとに発行した Gemini APIキー | 弊社 |
| スクリプトプロパティ `LINE_TOKEN` | お客様ごとの公式LINEのチャネルアクセストークン（長期） | 弊社 |
| 管理シートの「設定」タブ | 屋号・事業の説明・取り込み開始日など | お客様（初期設定の日に一緒に） |

## 1. 弊社の準備（最初に1回）

1. 保守用のGoogleアカウントを作る（ほかの用途に使わない。パスキーか物理キーでログイン、2段階認証は必須）
2. https://script.google.com/home/usersettings で「Google Apps Script API」をオンにする
3. `npx @google/clasp@2.4.2 login`（保守用アカウントで）
4. テンプレートを作る
   1. 新しいスプレッドシートを作り、名前を「管理シート」にする
   2. 拡張機能 → Apps Script を開き、プロジェクトの設定からスクリプトIDを控える
   3. `customers.json` に `{"name":"テンプレート","group":"template","scriptId":"…"}` を足し、`tools/deploy-all.sh --group template`
   4. スプレッドシートを開き直し、メニュー「経理」→「初期設定」を1回実行して動きを確かめる
   5. Apps Script のエディタで `管理用_テンプレートを空にする` を実行する。**スクリプトプロパティはコピーにも引き継がれるので、APIキーなどを残したまま配らないこと**
   6. 試しに作られた「経理_事業」フォルダを削除する
   7. 共有リンクの末尾 `/edit…` を `/copy` に変えたものが、お客様に送る「コピー用リンク」になる

## 2. お客様ごとの準備（弊社・初期設定の前に）

**Gemini APIキー**（請求をお客様ごとに分けるため、Google Cloud のプロジェクトをお客様ごとに作る）
1. Google Cloud でプロジェクト「keiri-お客様名」を作り、請求先アカウントにつなぐ（**有料の枠にする**：無料の枠は送ったデータがGoogleの改善に使われる可能性がある）
2. 「Generative Language API」を有効にし、APIキーを作る
3. キーの制限：使えるAPIを Generative Language API だけにする
4. 割り当て（クォータ）で1日あたりのリクエスト数に上限をつけ、予算アラート（例：月1,000円）を設定する
5. 毎月の利用額はプロジェクトごとの請求レポートで確認し、お客様への請求に使う

**公式LINE**（弊社のLINEビジネスIDで、お客様ごとに1つ作る）
1. LINE公式アカウントを作り、Messaging API を有効にする
2. 応答設定：「応答メッセージ」をオフ、「Webhook」をオン
3. チャネルアクセストークン（長期）を発行して控える
4. Webhook URL は初期設定の日に入れる（下の手順6）

## 3. 初期設定の日（お客様と画面共有で15〜20分）

1. お客様にコピー用リンクを開いてもらい、「コピーを作成」を押してもらう
2. 「設定」タブの「屋号」と「事業の説明」を一緒に書く
   - 事業の説明の例：「Webサイト制作とデザインの個人事業。自宅の一室が仕事場（家賃・電気代は3割を事業）。車は仕事と私用が半々。スマホは7割が仕事。取引先の広告費を立て替えることがある」
3. メニュー「経理」→「初期設定（最初に1回）」→ 許可画面で「許可」
   - 「このアプリはGoogleで確認されていません」と出たら、「詳細」→「（安全ではないページ）に移動」で進む（お客様自身のアカウントで動くコードのため、この表示が出る）
   - 経理フォルダ・今年の帳簿・毎日の自動実行（4時：メール、6時：カード明細）が自動で作られる
4. 拡張機能 → Apps Script →「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」→ 次のユーザーとして実行「自分」、アクセス「全員」→「デプロイ」
   - 表示された**ウェブアプリのURL**と**デプロイID**を控える
5. 経理フォルダを、弊社の保守用アカウントに「編集者」で共有してもらう
6. 弊社側で：
   - Apps Script のプロジェクトの設定 → スクリプトプロパティに `GEMINI_API_KEY` と `LINE_TOKEN` を入れる
   - LINE Developers の Webhook URL に「ウェブアプリのURL」＋`?k=合言葉` を入れる（合言葉はメニュー「経理」→「状態を確認」に出る。合言葉のない通知はすべて無視される）
   - `customers.json` に、お客様の名前・スクリプトID・デプロイIDを足す
7. お客様に公式LINEを友だち追加してもらい、「設定」タブの「LINE連携コード」（6桁）を送ってもらう →「登録しました」と返れば完了
8. 試しにレシートを1枚LINEで送り、数分後に「読み取りました」と届くことを確かめる

## 4. 更新の配布（お客様の操作は不要）

```bash
cd keiri-gas
# 1) src/00_config.js の APP_VERSION を上げる
# 2) テスト用 → 先行のお客様 → 全員 の順に配る
tools/deploy-all.sh --group test
tools/deploy-all.sh --group pilot
tools/deploy-all.sh
```

- 毎日の自動実行・LINEの読み取りは、配ったその時から新しいコードで動く
- **LINE受付（`doPost`）を変えたときだけ** `--redeploy-webapp` を付ける。ウェブアプリは公開した時点のコードで動くため。それ以外の変更では公開し直さない（下の「本番前に試すこと」A を確認するまでは、特に）
- `appsscript.json` の権限を増やすと、全員に許可し直してもらう必要が出る。権限は増やさない
- AIのモデル（`MODEL_NAME`）を上げるときは、テスト用のお客様で読み取り結果を確かめてから配る
- AIが答える前に「考える」量は `THINK_READ`（読み取り＝0）と `THINK_SHIWAKE`（仕分け＝1024）。考えた分も料金がかかる。読み取りの精度が足りなければ `THINK_READ` を少し上げる

## 5. 解約

1. 公式LINEを停止する（一定期間をおいて削除）
2. Google Cloud でそのお客様のAPIキーを削除する（これだけでAIの処理は確実に止まる）
3. `tools/deploy-all.sh --stop お客様名`：契約終了版に置き換える（LINEの受付のウェブアプリも置き換わる）。次に自動実行が動いたとき、自動実行と鍵がすべて消え、メニューは終了の案内だけになる
4. `customers.json` から外す。共有の解除はお客様にお願いする
5. 帳簿と領収書はお客様の手元に残る（保存期間は原則7年）

## 6. 本番前に試すこと（テスト用のGoogleアカウント2つで）

| | 確かめること | うまくいかないときの対応 |
|---|---|---|
| A | 弊社が `--redeploy-webapp` でウェブアプリを公開し直したあとも、LINEの写真がお客様のドライブに保存されるか（実行するユーザーが弊社に変わってしまわないか） | 変わってしまう場合は `--redeploy-webapp` を使わず、`doPost` を変えたときだけお客様に「デプロイを管理」→「編集」→「新バージョン」を押してもらう |
| B | LINE Developers の「検証」ボタンでエラーが出ても、実際のメッセージは届くか（GASのウェブアプリはリダイレクトを返すため）。`?k=合言葉` 付きのURLが受け付けられるか | 実際に届けば問題なし。「Webhookの再送」はオフのままにする |
| C | コピー用リンクで作ったコピーに、GASがついてくるか・スクリプトプロパティが空か | テンプレートで `管理用_テンプレートを空にする` をやり直す |
| D | 12月の日付のレシートを1月に送ったとき、前の年の帳簿に入るか | — |
| E | 「前年を締める」のあと、前の年の書類が今年の帳簿に入り、チェック欄に理由が出るか | — |
| F | 弊社が初期設定を押していない状態で、毎日の自動実行がお客様の権限で動いているか（実行数の画面で確認） | — |

## 7. まだ入っていないもの（次の段階）

- 期首残高・元入金の引き継ぎ（「前年を締める」で行う予定）
- 仕訳帳・総勘定元帳（複式簿記）と、青色申告決算書の転記用シート

- 固定資産台帳と減価償却

## 8. 旧版（Kanaさんの領収書あつめ v4.7 など）からの主な変更

- 年を固定していた部分（`TARGET_YEAR`・`LEDGER_ID`・`FOLDER_ID`）をなくし、取引日の年で帳簿とフォルダを自動で選ぶ・作る
- 受け取った日ではなく取引日で年を決める（12月分が1月に届いても前の年に入る）
- お客様ごとの内容（事業の説明・仕分けルール・カード名）を、コードから管理シートへ移した
- 台帳の「受信アカウント」列を「入手経路」に変え、「登録番号（インボイス）」列を足した
- 区分「会社の立替」を、どのお客様にも使える「立替（あとで精算）」にした
- AIのモデルを `gemini-flash-latest`（自動で変わる）から版を固定した名前にした
- ログに件名やファイル名を出さないようにした（弊社にもログが見えるため）
- 2アカウント対応と、v4.3以前のデータの後追い保存は外した
