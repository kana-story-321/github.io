# W3 デプロイ手順書 ─ ライフプランAI を "使える形" にする

## デプロイの3パターン

W1 の UI設計 で選んだ形式に応じて、デプロイ方法が変わる:

| UI形式 | デプロイ方法 | 難易度 | 共有先 |
|---|---|---|---|
| **A: サイドバー** | スプシを共有するだけ | ★☆☆ | スプシへのアクセス権を持つ人 |
| **B: Webアプリ** | GAS の Webアプリとして公開 | ★★☆ | URL を知る誰でも / 社内限定 |
| **C: Googleフォーム** | フォームURLを配布 | ★☆☆ | URL を知る誰でも |

---

## パターンA: サイドバー版のデプロイ (5分)

### 1. スプシの共有権限を設定

1. スプシ右上「共有」ボタン
2. 「一般的なアクセス」を "リンクを知っている全員" or 特定ユーザーに設定
3. 権限: **編集者** (実行時にスプシ書き込みが要るため)

### 2. 使い方を配布メンバーに周知

- スプシURL を Slack / メール / 社内Wiki で共有
- 「拡張機能 → Apps Script」から `onOpen` が動くので、メニュー「ライフプランAI」が表示される
- 初回のみ 各ユーザーで 権限承認 が必要

### 3. 動作確認

- 別アカウントでスプシを開き、メニュー「ライフプランAI」が出るか確認
- 「▶ シミュレーション実行」でテスト

---

## パターンB: Webアプリ版のデプロイ (10分)

### 1. GAS プロジェクトに Web App 追加コードを貼付

1. 既存の `Code_ライフプランAI.gs` はそのまま
2. 左の＋アイコン → 「スクリプト」→ ファイル名 **`Code_WebApp追加`** で新規追加
3. `W2_Code_WebApp追加.gs` の中身を貼付
4. 左の＋アイコン → 「HTML」→ ファイル名 **`WebApp`** で新規追加
5. `WebApp.html` の中身を貼付
6. 保存

### 2. Webアプリとしてデプロイ

1. GASエディタ右上「デプロイ」→「新しいデプロイ」
2. 種類の選択 (歯車アイコン) → **「ウェブアプリ」**
3. 設定:
   - 説明: `ライフプランAI v1.0`
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **自社の Workspace 全員** or **全員(限定なし)** の どちらか
     > ⚠️ 「全員(限定なし)」は 公開 URL になるので 社内限定にしたい場合は Workspace 選択
4. 「デプロイ」ボタン
5. **アクセス権を承認** (初回のみ、「安全ではない...」→「許可」)
6. 発行された **Webアプリの URL** をコピー

### 3. URL を配布

- Slack / メール / 社内Wiki で URL を共有
- 各ユーザーは URL を開くだけで使える (スプシを開かなくてOK)

### 4. 動作確認

- 別ブラウザ (シークレットモード) で URL を開く
- 入力フォームが表示される → 動作テスト

### 5. 更新の反映

- コードを修正したら、必ず「デプロイ」→「デプロイを管理」→ 既存デプロイの ✏編集アイコン → 「バージョン」を "新しいバージョン" に → 「デプロイ」
- 「デプロイ」を毎回 "新しいデプロイ" にすると URLが変わるので注意

## パターンC: Googleフォーム版のデプロイ (5分)

### 1. Googleフォームで入力フォーム作成

W1 の 顧客カルテ項目に対応する質問を作る (20〜30問):
- 短文回答: 氏名、職業
- 数値: 年齢、年収、貯蓄
- 選択式: 性別、配偶者有無、進学予定
- 段落: 気になるリスク、要望

### 2. フォーム回答時のトリガー設定

1. GAS プロジェクトで `onFormSubmit(e)` 関数を追加 (フォーム回答を受けてシミュレーション実行)
2. トリガー設定: GASエディタ「トリガー」→ 「+」→ イベントの種類: **フォームから送信時** → 関数: `onFormSubmit`
3. 権限承認

### 3. フォームURL を配布

- 「フォームを送信」→ URLコピー
- 若手営業などに配布、記入すると自動でシミュレーション実行 → 結果は担当ベテランにメール通知

## デプロイ時の 注意事項

### セキュリティ

- **API キー漏洩防止**: スクリプトプロパティ経由を厳守、コード直書き絶対 NG
- **アクセス範囲**: 顧客情報を扱うので、「全員(限定なし)」は避ける → Workspace限定 or 特定メールアドレス許可
- **顧客情報の匿名化**: 「顧客名(仮名OK)」を活用、テスト時は絶対に実顧客名を入れない

### 権限

- Webアプリ版で「次のユーザーとして実行」を **自分** にすると:
  - どのユーザーが使っても API 呼び出し・Docs 作成が自分の権限で動く
  - Gemini API の従量課金も自分に来る (無料枠内に注意)
- 「アクセスユーザー」を "自分" にすると 他人が使えない (デプロイの意味なし)

### バージョン管理

- 変更のたびに 「デプロイを管理」→ 既存デプロイの編集 → "新しいバージョン" を選択
- 「新しいデプロイ」で毎回作ると URL が増えて管理不能に

### 監査ログ

- 「シミュレーション履歴」シートを別途持ち、実行日時+顧客ID+実行者 を追記する運用推奨
- 個人情報保護の観点で "誰がいつ何を実行したか" 追える状態に

## トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| Webアプリ URL を開いても白画面 | 権限承認未完了 | GASエディタで手動で `doGet` を実行し権限承認 |
| 「このアプリは Google で確認されていません」 | 通常の表示、実害なし | 「詳細」→「安全ではないページに移動」→「許可」 |
| 別ユーザーで実行できない | アクセス権限が「自分」になっている | デプロイ管理で アクセスユーザー を変更 |
| コード変更が反映されない | デプロイの再デプロイ忘れ | 「デプロイ管理」→ 編集 → 新しいバージョン |
| API エラー (429) | 無料枠のレート制限 | 1-2分待ってリトライ、頻用なら課金検討 |
| Docs 生成が遅い | Webアプリの制限時間(6分) | シミュレーション期間を40年→30年に短縮 |
