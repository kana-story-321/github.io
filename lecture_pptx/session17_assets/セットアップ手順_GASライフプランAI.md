# 第17回 W02 ライフプランAI ツール セットアップ手順 (GAS)

## 完成イメージ

- スプシ「顧客カルテ」シートに 相談者情報を書き込む
- メニュー「ライフプランAI」→「シミュレーション実行」
- 30秒後、以下が自動生成される:
  - **「シミュレーション結果」シート**: 40年ぶんの年次CF表 + サマリ + 貯蓄残高の折れ線グラフ
  - **「保険提案フック」シート**: シミュから浮かぶ提案候補 3〜5件
  - **サイドバー**: サマリと提案フックのダイジェスト表示

---

## 事前準備 (15分)

### 1. Gemini API キーを取得

1. [Google AI Studio](https://aistudio.google.com/apikey) にログイン
2. 「Create API key」→ 新しいプロジェクトを選択
3. 表示された `AIzaSy...` で始まる文字列を **メモ帳に一時保存**

> ⚠️ このキーは鍵と同じ。他人と共有しない、コードに直書きしない。

### 2. スプシと GAS プロジェクトの準備

1. `ライフプラン入力テンプレ.xlsx` を Google ドライブへアップロード
2. 右クリック →「Google スプレッドシートで開く」
3. シート名が **「顧客カルテ」「前提テーブル」** であることを確認(GAS がこの名前で読む)
4. メニュー「拡張機能」→「Apps Script」で エディタを開く

### 3. コードを貼り付け

1. デフォルトの `Code.gs` を全消し → **`Code_ライフプランAI.gs` の中身を貼付**
2. 左の＋アイコン → 「HTML」→ ファイル名 **`Sidebar`** で新規追加
3. `Sidebar.html` の中身を貼付
4. 左の＋アイコン → 「スクリプト」→ ファイル名 **`Code_レポート生成`** で新規追加
5. `Code_レポート生成.gs` の中身を貼付
6. `Code_レポート生成.gs` の冒頭 `AGENCY_NAME` 定数に自社の代理店名を書く
7. 保存(Ctrl+S / Cmd+S)

### 4. Gemini API キーをスクリプトプロパティに登録

1. GAS エディタ左サイドバー「⚙ プロジェクトの設定」
2. 下にスクロール →「スクリプト プロパティ」→「スクリプト プロパティを追加」

| プロパティ | 値 |
|---|---|
| `GEMINI_API_KEY` | (メモしておいた AIzaSy... の文字列) |

3. 「スクリプトプロパティを保存」

### 5. 初回動作確認

1. GAS エディタで 関数選択ドロップダウンから `testSetup` を選び「実行」
2. 初回は権限承認画面 → 「詳細」→「安全ではないページに移動」→「許可」
3. 実行ログ(下部)に以下が出れば成功:
   ```
   GEMINI_API_KEY: AIzaSy...(OK)
   顧客カルテ 項目数: 0     ← 空欄なので0でOK
   前提テーブル 項目数: 18
   ```

### 6. スプシに戻ってメニュー確認

1. スプシのタブに戻り、**再読み込み(F5)**
2. メニューバーに **「ライフプランAI」** が表示されることを確認

## 動作テスト (10分)

### テスト1: 記入例をコピーして実行

1. 「顧客カルテ_記入例」シートを開く
2. B列(値列)を全選択 → コピー
3. 「顧客カルテ」シートの B列に貼付
4. メニュー「ライフプランAI」→「▶ シミュレーション実行」
5. 「開始」→「OK」→ 30秒待つ → 「完了」アラート

### 期待結果

- 「シミュレーション結果」シート:
  - 40行のCF表(2026〜2065年)
  - 収支マイナスの年は赤、貯蓄200万以下の年は黄で色分け
  - 貯蓄残高の折れ線グラフ
  - サマリ(最大貯蓄年 / 最低貯蓄年 / 破綻年 / リスク期間 / 総評コメント)
- 「保険提案フック」シート:
  - 3〜5件の提案候補(トリガー / 商品タイプ / 金額ヒント / 提案理由)
- サイドバー(メニュー「サイドバーを開く」で確認):
  - サマリ + 提案フックのダイジェスト

### テスト2: 前提を変えて再実行

1. 「前提テーブル」シートで 投資リターンを 2.0% → 4.0% に変更
2. 「▶ シミュレーション実行」を再実行
3. 貯蓄残高が全期間で上振れすることを確認 → 顧客に「前提次第で結果が変わる」を可視化できる

### テスト3: 破綻シナリオ

1. 「顧客カルテ」の 年収 を 600 → 200 万 に変更
2. 実行 → 破綻年が出ること、総評で対策が示唆されることを確認

### テスト4: 顧客向けレポート出力 (PDF)

1. シミュレーション実行後、メニュー「ライフプランAI」→「📄 顧客向けレポート出力 (PDF)」
2. 数十秒待つ → 完了アラートに Google Docs と PDF の URL が表示される
3. Google Drive に「ライフプランレポート」フォルダが自動作成され、以下2ファイルが保存される:
   - `ライフプラン診断レポート_田中太郎様_2026-07-15.pdf` (お客様配布用)
   - 同名の Google Docs (代理店側で編集可能な原稿)
4. PDF を開き、7ページ構成を確認:
   - **表紙**: レポート名 / お客様名 / 相談日 / 担当代理店
   - **お客様情報**: 相談者/年収/家族/資産/住宅ローン/月次支出/ライフイベント/リスク/要望
   - **総評**: AI総評コメント + 最大貯蓄年/最低貯蓄年/破綻年/リスク期間
   - **貯蓄残高の推移グラフ** (スプシから画像として埋め込み)
   - **年次キャッシュフロー表** (40年、収支マイナス赤、貯蓄マイナス濃赤)
   - **保険提案フック** (備えの候補)
   - **前提条件と免責事項** (最終ページ)

> ⚠️ お客様に渡す前に **Google Docs 側で内容確認+編集** を推奨。AI総評コメントは
> 顧客トーンに書き直し、代理店名・ロゴを整えてから PDF を再エクスポートすると "自社仕様" のレポートに。

## 動作しないとき (トラブルシューティング)

| 症状 | 原因と対処 |
|---|---|
| メニュー「ライフプランAI」が出ない | スプシを再読み込み(F5)。それでも出ないなら GAS エディタで `onOpen` を手動実行 |
| 「GEMINI_API_KEY が未設定」 | スクリプトプロパティに正しく登録できていない。プロパティ名は完全一致 |
| 「Gemini API エラー (429)」 | 無料枠のレート制限。1〜2分待ってリトライ |
| 「Gemini API エラー (400)」+ payload 長い | プロンプトが長すぎ。顧客カルテの自由記述を短くする、または期間を30年に短縮 |
| 「シート「顧客カルテ」が見つかりません」 | シート名を「顧客カルテ」に。Code 冒頭の `KARTE_SHEET` 定数と一致必須 |
| CF表の数値が明らかに変(貯蓄が急増急減) | Gemini の数値精度限界。安全側では GAS 側で累積計算を担当する改修が推奨 |
| 保険提案フックが空 | プロンプトで hooks 3件以上を強制、または顧客カルテの「気になるリスク」欄を具体的に |
| 40年ぶんの計算が長い(1分超え) | Gemini 2.5 Flash → Pro に切替(精度UPだが遅くなる)、または期間を30年に短縮 |

## 発展課題 (演習2 の後半 or 復習)

1. **数値検証の GAS 追加**: 生成された CF 表の "前年貯蓄 + 当年収支 = 当年貯蓄" を GAS 側で再計算・照合
2. **PDF レポート化**: 「シミュレーション結果」シートを PDF 化(GAS の `DriveApp` 使用)、顧客説明資料へ
3. **判定履歴の蓄積**: 顧客ごとに実行結果を別スプシに保存、半年ごと再試算で "前回との差分" を追える
4. **第15回マスタ表との接続**: 保険提案フックの `product_type` を第15回引受判定マスタ表と照合、
   「この提案を A社医療プレミアム で出せそうか」まで即引き
5. **What-if 分析**: 前提テーブルを 3パターン(楽観/中位/悲観)持って 3回連続実行 → 結果を横並び比較

## 運用のコツ

- **月1回の前提テーブル見直し**: 経済前提と教育費相場は 年1回 は最新値で更新
- **面談中にリアルタイム試算**: 顧客の目の前で数値を書き換えて再実行 → 「投資リターン 2%→4% で老後 500万上振れます」等を可視化
- **AI 出力の "3つの必ず"**: 貯蓄残高の累積を目視 / 総評コメントは顧客トーンで書き直す / 保険提案は代理店の商品ラインナップに落として提案
