### 「情報設計」シートの構成 (穴埋めワークシート)

| 列 | 内容 | 誰が埋める |
|---|---|---|
| A: 項目 | ターゲット/カテゴリ/情報源/フォーマット等 (13行) | 事前に埋め済み |
| B: 考え方・判断基準 | **なぜこの項目を決める必要があるか** の解説 | 事前に埋め済み(講師が解説) |
| C: あなたの答え | **生徒が自分の運用に合わせて記入** | 演習1で生徒が埋める |
| D: 例 | 参考例 (そのまま写さない) | 事前に埋め済み |

→ 演習1 は「B列(考え方)を読む → Geminiと相談 → C列(あなたの答え)を書く」の流れ。
「Gemini相談ログ」シートに、質問と結論を残していく運用。

## セットアップ手順 (講師デモ用: 30分)

### 1. スプシの取り込み

1. `お金情報配信_デモデータ.xlsx` を Google ドライブへアップロード
2. 右クリック →「アプリで開く」→「Google スプレッドシート」で開く
3. 3シート (情報設計 / 情報源マスター / 配信予約) が入っていることを確認

### 2. GAS プロジェクトの用意

1. スプシで「拡張機能」→「Apps Script」
2. デフォルトの `Code.gs` を消して、`Code_情報収集.gs` の中身を貼る
3. 左の＋アイコン → スクリプト → ファイル名 `Code_LINE配信` で新規追加
4. `Code_LINE配信.gs` の中身を貼る
5. 保存

### 3. Gemini API キー

1. [Google AI Studio](https://aistudio.google.com/apikey) で発行
2. GAS の「⚙ プロジェクトの設定」→「スクリプト プロパティ」

    | プロパティ | 値 |
    |---|---|
    | `GEMINI_API_KEY` | AIzaSy... |

3. エディタで `verifyModel` を実行 → `✅ gemini-2.5-flash は利用可能` を確認

### 4. LINE Messaging API チャネル

⚠️ **重要**: 既に Lステップと連携している公式LINE アカウントに対して、
Messaging API チャネルを作成します。**Webhook 設定は絶対に触らないでください。**

1. [LINE Developers](https://developers.line.biz/console/) にログイン
2. 対象のプロバイダーを選択 (or 新規作成)
3. 「新規チャネル作成」→「Messaging API」を選択
4. チャネル名など必要事項を入力して作成
5. 作成後の「Messaging API 設定」タブを開く
6. 「チャネルアクセストークン (長期)」を「発行」→ トークンをコピー
7. **「Webhook 設定」タブは開かない、触らない** ⚠️
   - 開いてしまってもURLは絶対に変更しない
8. 対象の公式LINE アカウントと Messaging API を紐付け(既存連携済みの場合はそのまま)

### 5. LINE 用スクリプトプロパティ

GAS の「スクリプト プロパティ」に以下を追加:

| プロパティ | 値 | 説明 |
|---|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | 上でコピーした長期トークン | 送信認証鍵 |
| `ADMIN_EMAIL` | 自分のメールアドレス | エラー時通知先 |
| `MONTHLY_LIMIT` | `200` | 無料枠上限 |
| `FRIEND_COUNT_FALLBACK` | `20` (概算の友だち数) | Insight API失敗時に使う |

## 動作確認 (30分)

### A. 情報収集GAS

1. GAS エディタで **`collectOne`** を実行 (初回は権限承認)
2. スプシ「配信予約」シートに1行追加される
3. 出典URLがホワイトリスト内のドメインになっているか確認
4. `collectAllCategories` で4カテゴリ一気収集も可能

### B. OK判定

1. スプシ「配信予約」の F列 (OK/NG) に `OK` を入力
2. A列の日付が「今日日付」であることを確認

### C. LINE配信GAS

1. `MONTHLY_LIMIT` を一時的に `10` に変更 (`testLowLimit` 実行でもOK)
2. **`sendOne`** を実行
3. 自分の個人LINE (対象公式アカウントを友だち追加済み) に配信が届く
4. G列 (配信済み日時) に今日日時が入っている
5. 上限超のテスト: 何度か実行して自動停止+通知メール確認
6. テスト完了後、`resetLimit200` で 200 に戻す + `resetQuotaCounter` でカウンタ初期化

### D. 自動化

1. `installDailyTrigger` を実行 → 毎日9時台に sendOne 自動実行の予約完了
2. 手動でトリガーを追加する場合: 時計アイコン「トリガー」→ ハンドラ`sendOne` / 日ベース / 午前9-10時

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| 収集GAS で出典URLがホワイトリスト外 | プロンプトのホワイトリスト強調文を強くする、`isDomainAllowed_` でスキップ確認 |
| Search Grounding が動かない | モデル名を `gemini-2.5-flash` に、リージョン制限がないか確認 |
| broadcast がエラー | チャネルアクセストークンの権限、対象公式LINE と紐付け確認 |
| Webhookを間違って開いた/変えた | すぐに元のLステップWebhookのURLに戻す (Lステップ管理画面で確認) |
| 通数カウンターが月替わりリセットされない | MONTH_YYYYMM プロパティを目視で確認、`resetQuotaCounter` で強制リセット |

## 継続運用のコツ

- **配信予約の在庫確保**: `collectAllCategories` を週1回手動で走らせて、4本ずつストックしておく
- **OK判定は朝一で**: 配信は9時、確認は8時までに済ませる運用に
- **月末の通数チェック**: 月末に MONTHLY_COUNT を目視、翌月への持ち越し戦略を決める
- **ホワイトリストの拡張**: 新しい公的サイトが必要になったら「情報源マスター」に追記するだけ、コード修正不要
