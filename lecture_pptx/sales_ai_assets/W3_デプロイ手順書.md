# W3 デプロイ手順書 ─ 営業ノウハウAI を使える形に

## デプロイ方法(選んだ作り方別)

W1 で選んだ作り方に応じて、手順が変わります。

### NotebookLM 版を選んだ場合

**基本は "共有" だけ**

1. NotebookLM のノートブック右上「共有」
2. 若手営業のメールアドレスを追加
3. 権限: **「閲覧可(チャット可能)」** で共有(編集不可、ソースを守る)
4. Slack / メールで NotebookLM の URL を配布
5. 使い方1枚メモ を添付(「まずここに質問してね、答えられない時は先輩に」)

### GAS 版を選んだ場合

**サイドバー版 or Web アプリ版から選ぶ**

#### A. サイドバー版(簡単・推奨)

1. スプシ右上「共有」→ 若手営業のメールアドレスを追加
2. 権限: **編集者**(サイドバーの実行にスプシ書き込みが必要)
3. スプシ URL を Slack で配布
4. 若手はスプシを開く → メニュー「営業ノウハウAI」→ 使う
5. ⚠️ アクセス範囲を "全員(公開)" にしない、Workspace内 or 特定ユーザーに限定

#### B. Web アプリ版(URL 配布・スマホ対応)

1. GAS エディタ「デプロイ」→「新しいデプロイ」→ 種類:「ウェブアプリ」
2. 設定:
   - 説明: 「営業ノウハウAI v1.0」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **Workspace内 全員**
3. デプロイ → URL 発行
4. 別ブラウザ(シークレット)で URL を開いて動作確認
5. URL を配布

## 決めておくこと(運用ルール)

デプロイ前に チームで合意しておくべき5点:

### 1. 誰が使う?

- 新人・若手営業(1〜3年目)を中心に
- ベテランは "月1回 ノウハウ追加" の役割
- 管理職は "質問履歴の分析" の役割

### 2. 何を聞いていい / 聞かないほうがいい?

**聞いていい**:
- 営業のコツ・話術・反対処理
- 顧客タイプ別の対応
- 過去の成功・失敗事例

**聞かないほうがいい(法的リスク・機微)**:
- 個別商品名の推奨判断(→ 上司+コンプラ確認)
- 特定顧客の判断(→ 顧客情報は個別に管理)
- 法律・税務の判断(→ 専門家)

### 3. AI 回答をどう扱う?

- **AI 回答は "参考"、判断は 人**
- そのまま顧客に伝えず、自分の言葉に置き換える
- 「なぜこの回答なのか」の根拠(参照ノウハウID)を確認

### 4. ノウハウ更新は誰が?

- **担当ベテラン営業(月1回、5〜10分)** で追記
- 質問履歴を月1回見返す担当を決める
- 「AIが答えられなかった質問」→ 次月に追加

### 5. 個人情報の扱い

- 質問には 顧客名・電話番号等 を含めない
- 「40代 高血圧の男性のお客様」等の 属性表現で
- 質問履歴の閲覧権限を絞る(管理職のみ 等)

## 動作テスト (デプロイ後 30分)

`W3_テストデータ.xlsx` の 10質問を順に投げて、期待通り動くか確認。

**チェック観点**:
- カテゴリ一致(期待カテゴリと合っているか)
- キーメッセージ一致(期待の骨子が入っているか)
- トーン適切(先輩っぽい、共感入り)
- 決めゼリフあり(具体的セリフが入っているか)
- 若手が読んで "実践できそう" と感じるか

結果を「テスト結果記録」シート(W3_テストデータ.xlsx内)に○△×で記入。

## 継続改善のサイクル

```
[週次]                       [月次]                        [年次]
質問履歴を見返し             ベテランがノウハウ追加        全ノウハウ棚卸し
   ↓                            ↓                            ↓
"答えられなかった質問"       トーン微調整                  古い情報を無効化
   ↓                            ↓                            ↓
新ノウハウ追加                 質問傾向をヒアリング          利用者から満足度調査
```

## トラブル・想定外への対応

### 若手が使ってくれない

- 最初の1週間は「一緒に横で使う時間」を作る
- 「うちの新入社員が困った時、ここに聞いてみて」を Slack でリマインド
- 使った若手を Slack で紹介(「〇〇さんが今日 AI に聞いてくれました!」)

### AI 回答の質が下がってきた

- 質問履歴を見返し、"答えられなかった" 傾向を分析
- ノウハウを追加、または トーン(TONE 定数)を微調整
- 半年に1回は "AI 回答の抜き打ちレビュー"(20件くらい)

### 業務外の質問が来る

- サイドバーに「業務外の質問は答えられません」等の注意書き追加
- プロンプトに「営業関連以外の質問には答えない」を明示

## 発展課題

1. **音声入力対応**: 質問を音声で入力(HTMLに Web Speech API)
2. **LINE連携**: 若手が LINE で質問 → AI が LINE で回答(第11回応用)
3. **ノウハウ自動抽出**: 商談録音の文字起こし → AI がノウハウ候補を抽出
4. **成約率との相関**: 質問履歴 と 個人の成約率を分析(誰が よく使っているか)
5. **多言語対応**: 英語圏の営業向けに 英語でも回答(Gemini はマルチリンガル)
