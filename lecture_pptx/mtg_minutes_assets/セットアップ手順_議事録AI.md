# 議事録AI セットアップ手順 (AI初心者向け丁寧版)

## 完成イメージ

1. スプシ「MTG記録」シートに 会議名 / 日時 / 参加者 / 文字起こし本文 を入力
2. メニュー「議事録AI」→「▶ 議事録生成」
3. 30秒後、Google Docs に議事録が生成される
4. 内容確認 → 修正 → 「📧 参加者にメール送信」で配布

---

## 事前準備 (15分)

### 1. Gemini API キーを取得 (5分)

1. [Google AI Studio](https://aistudio.google.com/apikey) にログイン (普段の Gmail アカウントでOK)
2. 「Create API key」→ 新しいプロジェクトを選択
3. 表示された `AIzaSy...` で始まる長い文字列を **メモ帳に一時保存**

> ⚠️ このキーは 鍵と同じ。他人と共有しない、SNS に貼らない、コードに直書きしない。

### 2. スプシと GAS プロジェクトの用意 (5分)

1. `MTG記録_テンプレ.xlsx` を Google ドライブへアップロード
2. 右クリック → 「Google スプレッドシートで開く」
3. シート名が **「MTG記録」** であることを確認 (GAS がこの名前で読む)
4. メニュー「拡張機能」→ 「Apps Script」で エディタを開く

### 3. コードを貼り付け (2分)

1. デフォルトの `Code.gs` を全消し → **`Code_議事録AI.gs` の中身を貼付**
2. 保存 (Ctrl+S / Cmd+S)

### 4. Gemini API キーをスクリプトプロパティに登録 (2分)

1. GAS エディタ 左サイドバー「⚙ プロジェクトの設定」
2. 下にスクロール → 「スクリプトプロパティ」→ 「スクリプトプロパティを追加」

| プロパティ | 値 |
|---|---|
| `GEMINI_API_KEY` | (メモしておいた AIzaSy... の文字列) |

3. 「スクリプトプロパティを保存」

### 5. 初回動作確認 (1分)

1. GAS エディタで 関数選択ドロップダウンから `testSetup` を選び「実行」
2. 初回は 権限承認画面 → 「詳細」→ 「安全ではないページに移動」→ 「許可」
   > 💡 これはあなた自身が書いた(貼付けた)スクリプトなので、許可して大丈夫です
3. 実行ログ (下部) に以下が出れば成功:
   ```
   GEMINI_API_KEY: AIzaSy...(OK)
   会議名: 週次営業会議
   日時: 2026-07-20 (月) 10:00-10:35
   参加者: 田中, 佐藤, 山田, 鈴木
   文字起こし文字数: 0     ← まだ本文貼付前なので 0 でOK
   ```

### 6. スプシに戻ってメニュー確認 (30秒)

1. スプシのタブに戻り、**再読み込み (F5)**
2. メニューバーに **「議事録AI」** が表示されることを確認

## 動作テスト (10分)

### テスト1: サンプル文字起こしで議事録生成

1. `サンプル文字起こし.md` を開き、**「## 文字起こし本文」以下の全内容** をコピー
2. スプシ「MTG記録」シートの **「文字起こし本文」の下の広いセル** に貼付
3. メニュー「議事録AI」→「▶ 議事録生成」
4. 開始アラート → 「OK」→ 30秒待つ
5. 完了アラートに Google Docs の URL が表示される → クリックで開く

### 期待結果

Google Docs に以下の議事録が生成される:

- **タイトル**: 【議事録】週次営業会議
- **メタ情報表**: 日時 / 参加者 / 作成者
- **議題**: 3つ程度 (週次営業状況共有 / 新商品説明会準備 / 議事録AI化)
- **決定事項**: 3〜4件 (妊娠中お客様の対応 / 説明会参加者 / 議事録AI化を9月議題に)
- **ToDo表**: 4〜5件 (山田: B社確認 7/25まで / 鈴木: 説明会登録 7/22まで / etc.)
- **保留事項**: 該当があれば
- **次回予定**: 2026-07-27 (月) 10:00

### テスト2: 自社の実MTGでやってみる

1. Zoom で実際のMTGを開催 (or 過去のMTG録画を使う)
2. Zoom の文字起こしをダウンロード (.txt or .vtt)
3. スプシに貼付 + 会議名/日時/参加者 を更新
4. 「▶ 議事録生成」
5. 出力を確認 → 修正 → 手作業で作った議事録と比較

### テスト3: メール送信テスト

1. 「議事録生成」の後、メニュー「📧 参加者にメール送信」
2. 自分のメールアドレスだけ入れて送信 (テストなので)
3. Gmail に議事録リンク付きメールが届くことを確認
   > 💡 初回は Gmail の送信権限承認が要る場合あり

## 動作しないとき (トラブルシューティング)

| 症状 | 原因と対処 |
|---|---|
| メニュー「議事録AI」が出ない | スプシを再読み込み (F5)。それでも出ないなら GAS エディタで `onOpen` を手動実行 |
| 「GEMINI_API_KEY が未設定」 | スクリプトプロパティに正しく登録できていない。プロパティ名は 完全一致 (スペース禁止) |
| 「文字起こし本文が短すぎます」 | 文字起こし本文欄に 100文字以上貼付されているか確認。「(ここに...)」のサンプル文言が残っていたら削除 |
| 「Gemini API エラー (429)」 | 無料枠のレート制限、1-2分待って再実行 |
| 「Gemini API エラー (400)」 | 文字起こしが長すぎ (5万文字超え等)。30分MTG想定を超えている場合は分割 |
| ToDo が期待より少ない | 文字起こしで "誰が" "いつまでに" が話されているか確認。曖昧なものは pending に回る |
| 参加者名が全部認識されない | メタ情報の「参加者」欄をカンマ区切りで正確に (例: `田中, 佐藤, 山田`) |
| メール送信で「認証エラー」 | 初回 Gmail 権限承認が要る。testSetup で権限承認を先に済ませる |
| Docs のフォーマット崩れ | Docs 側で直接編集して修正。必要なら再生成 |

## 承認・配布の運用ルール (演習2 で決めること)

議事録は AI が作った "草案"、そのまま配布しないルールを決める:

### 承認手順 (例)
1. 議事録生成 直後、司会者が Google Docs で目視確認 (3-5分)
2. 決定事項・ToDo・期限 が 文字起こしと一致しているか確認
3. 顧客名・個人情報の扱いに問題がないか確認
4. 必要に応じて修正
5. **確認済みマーク**(例: タイトルに ✓ 追加)を付けて承認完了

### 配布方法
- メニュー「📧 参加者にメール送信」で自動配布
- または Docs URL を Slack / チャットに共有
- 議事録アーカイブ(Google Drive の「議事録アーカイブ」フォルダ)にも自動保存済み

### やってはいけないこと
- ⚠️ AI 生成直後にレビューなしで自動配布(参加者の名前や決定が捏造されている可能性)
- ⚠️ 顧客名や個人情報を含む会議で 承認前に外部共有
- ⚠️ 「AI がやってくれるから」と司会者が MTG に集中しない (むしろ集中できる時間が増える設計)

## 発展課題

1. **Zoom → スプシ自動連携**: Zoom Webhook で 文字起こしを自動貼付
2. **議事録アーカイブ検索**: 過去議事録を Gemini に検索させる
3. **ToDo → Google Tasks 連携**: 抽出した ToDo を自動でタスク登録
4. **Slack 通知**: 議事録生成完了 → Slack に投稿
5. **多言語対応**: 英語 MTG → 日本語議事録
