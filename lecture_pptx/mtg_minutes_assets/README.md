# 議事録自動生成ワーク(オンラインMTG文字起こし → 議事録AI)

## 想定シチュエーション

社内でオンラインMTG(Zoom / Teams / Google Meet)を毎週開催している。
録画・文字起こしは各ツールが自動でやってくれるが、**そこから議事録を作るのは司会者の手作業**で、
30分MTGで議事録作成に 30〜40分かかる状態。年間で数十時間を圧迫する。

**GAS + Gemini API** で 「文字起こしを貼り付けて実行ボタン → 30秒で Google Docs の議事録草案」まで自動化する。
承認・配布まで含めて 1本の流れとして設計する。

---

## AI初心者向けの学び方

1. **まず 業務フロー を見える化**(演習の1つ目)。「今どこを人がやってて、どこを AI に任せられるか」を書き出す
2. **議事録テンプレを設計**(演習の2つ目)。「AI にどんな形で議事録を返してほしいか」を JSON で決める
3. **GAS を貼って動かす**(バイブコーディング)。細かい理解は後回し、まず動かして体験
4. **承認・配布フローを回す**。AI が作った草案を人が確認 → メール配布

## 業務フローの整理(演習1 の到達物)

### 「議事録作成」の 9ステップ(週次営業会議 30分 の例)

| # | ステップ | 誰が | 時間 | 区分 | AI化? |
|:-:|---|---|:-:|:-:|:-:|
| 1 | MTG開催 | 参加者 | 30分 | 手動 | × |
| 2 | 文字起こし生成 | Zoom | (自動) | 自動 | × |
| 3 | 文字起こしDL | 司会者 | 1分 | 半自動 | △ |
| 4 | スプシに貼付 | 司会者 | 1分 | 手動 | △ |
| 5 | メタ情報入力 (会議名/日時/参加者) | 司会者 | 2分 | 手動 | × |
| 6 | **議事録草案生成** | **GAS + Gemini** | **30秒** | **自動** | **○** |
| 7 | 内容確認・承認 | 司会者 | 3-5分 | 手動 | × |
| 8 | 修正 | 司会者 | 2-3分 | 手動 | △ |
| 9 | 参加者にメール配布 | GAS 自動送信 | 10秒 | 半自動 | ○ |

### 削減効果

| Before | After | 削減 |
|---|---|---|
| 30-40分/回 (議事録作成) | 8-12分/回 (メタ入力+確認+修正+配布) | **約20-30分/回** |
| 週1回 = 年間 26〜35時間 | 週1回 = 年間 7〜10時間 | **約20時間/年** |

## 議事録テンプレの設計(演習2 の到達物)

### 議事録に載せる項目(AI が抽出 or 人が入力)

| 項目 | 担当 |
|---|---|
| 会議名 / 日時 / 参加者 | 人が入力(スプシ) |
| 議題(アジェンダ) | AI が抽出 |
| **決定事項**(topic / decision / reason) | **AI が抽出** ★ |
| **ToDo**(who / what / due) | **AI が抽出** ★ |
| 保留事項 | AI が抽出 |
| 次回予定 | AI が抽出 |
| 議事録作成者 | 人が入力(GAS 自動でも可) |

### AI に返させる JSON 構造 (W02 で GAS の responseSchema にそのまま使う)

```json
{
  "agenda": ["議題1", "議題2", ...],
  "decisions": [
    { "topic": "...", "decision": "...", "reason": "..." },
    ...
  ],
  "todos": [
    { "who": "山田", "what": "...", "due": "2026-07-25" },
    ...
  ],
  "pending": [ { "topic": "...", "next_action": "..." }, ... ],
  "next_meeting": { "date": "...", "topics": [...] }
}
```

なぜ JSON? → AI に自由文で書かせると形式バラバラで GAS が扱えない。JSON なら「決定事項の3件目」と機械的に取り出せる。

## セットアップ手順(講師デモ用: 15分)

詳細は `セットアップ手順_議事録AI.md` を参照。

1. `MTG記録_テンプレ.xlsx` を Google ドライブへアップ → スプシで開く
2. 拡張機能 → Apps Script → `Code_議事録AI.gs` の中身を貼付
3. スクリプトプロパティに `GEMINI_API_KEY` を設定
4. `testSetup` を実行 → 権限承認
5. スプシに戻ってメニュー「議事録AI」→「▶ 議事録生成」

## ワーク中に必ず伝える「意味」の問いかけ

| タイミング | 問いかけ |
|---|---|
| 業務フロー棚卸しの前 | 「今 議事録作りに何分かかってる?年間で何時間?」→ 削減効果の実感 |
| 手動/半自動/自動 色分け時 | 「"文字起こしDL" は今 半自動、これを自動にする価値ある?→ 頻度次第」 |
| AI化検討時 | 「決定事項の抽出は AI 得意、でも "承認" は人。なぜ?→ 責任と最終判断」 |
| JSON構造を決めた時 | 「なぜ自由文じゃなく JSON?→ GAS が機械的に扱える」 |
| GAS を動かした後 | 「AI が抜けてる ToDo あった?→ 現段階での AI の限界を体感」 |
| 承認フローの前 | 「AI 出力そのまま配布は危険。誰が/何を/いつ 確認するか決める」 |
| 配布の前 | 「メールを AI が自動送信していい?→ 承認後 なら OK、それ以外は NG」 |

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| 「文字起こし本文が短すぎます」 | MTG記録シートの「文字起こし本文」欄に 100文字以上貼付されているか確認 |
| 「Gemini API エラー (429)」 | 無料枠のレート制限、1-2分待ってリトライ |
| 「Gemini API エラー (400)」 | 文字起こしが長すぎ (5万文字超え等)。分割して2回に |
| ToDo が抽出されない | 文字起こしで "誰が" "いつまでに" が言われているか確認。曖昧なものは AI が pending に入れる |
| 議事録の内容が捏造されている | プロンプトに「推測で追加しない」と書いているが確認、Docs 側で修正必須 |
| メール送信でエラー | 初回は Gmail 権限承認が必要。実行ログ確認 |

## 発展課題

1. **Zoom → スプシ自動連携**: Zoom Webhook で文字起こしを自動貼付(ステップ3-4 の自動化)
2. **議事録アーカイブ検索**: 過去の議事録から「〇〇について前回どう決まった?」を GAS で検索
3. **ToDo → Google Tasks 連携**: ToDo を自動で Google Tasks に登録
4. **Slack 通知**: 議事録生成完了 → Slack にリンクとサマリ投稿
5. **多言語対応**: 英語MTGの文字起こしから日本語議事録を生成(Gemini はマルチリンガル)
