## 「引受判定マスタ」の10列(設計の中核)

| # | 列 | 内容 |
|:-:|---|---|
| A | 条件ID | RULE-XXX |
| B | 保険会社 | A社生命 / B社生命 / C社生命 / D社生命 / F社生命 |
| C | 商品名 | 医療プレミアム / 死亡プレミアム / 学資保険 / 医療スタンダード 等 |
| D | カテゴリ | 年齢 / 健康 / 職業 / 既往歴 / 金額 / その他 |
| E | 条件詳細 | 顧客の状態を自然言語で(例: 高血圧180超) |
| F | この商品での判定 | YES / YES(条件付) / 要確認 / NO |
| G | 判定理由 | 1〜2文で "なぜ" |
| H | 対応 | 追加確認 / NG時の代替商品 / 再申込タイミング |
| I | 情報源 | 会社研修§ / 営業担当メール / 先輩口伝 / 過去謝絶 |
| J | 最終更新 | 日付+更新者 |

## 発展課題

1. **判定履歴分析**: 半年分の履歴から "よく発火する条件" を発見→ルール強化
2. **他ツール連携**: 保険会社の申込システムと直接連携
3. **顧客向けPDF**: 判定結果を PDF化 → 顧客説明資料に
4. **通知連携**: NG判定時に 担当マネージャーに Slack通知
5. **一括判定**: 顧客リスト(スプシ10行)を一括判定
