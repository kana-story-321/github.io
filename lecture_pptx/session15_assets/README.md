# 第15回 デモ資材 — 保険代理店の「事前引受スクリーニング」マスタ表

## 想定シチュエーション

**保険代理店** として複数社の保険商品を扱っている。
お客様に商品を提案 → 申し込み → 保険会社に送る → **謝絶** される事案がしばしば発生。
「申し込んだのに落ちた」という残念な体験を減らしたい。

**そのためには**、各社の引受基準を代理店側で先に把握し、AI に一次判定させて
「この人は A社NG だけど B社なら通るかも」を **申し込み前** に見立てる仕組みが要る。

## 「引受判定マスタ表」の列設計 (10列)

| 列 | 名前 | 説明 | 記入例 |
|---|---|---|---|
| A | 条件ID | `RULE-001` などの一意ID(削除より "無効化" 推奨) | RULE-003 |
| B | カテゴリ | 年齢 / 健康 / 職業 / 既往歴 / 金額 / その他 | 健康 |
| C | **保険会社** | A社生命 / B社生命 / C社生命 / D社生命 / F社生命 / 全社共通 | A社生命 |
| D | 商品ジャンル | 医療 / がん / 死亡 / 学資 / 介護 / 医療(緩和型) | 医療 |
| E | 条件詳細 | 顧客の状態を自然言語で具体的に | 高血圧 180超 |
| F | 判定 | YES / YES(条件付) / 要確認 / NO | NO |
| G | 判定理由 | 1〜2文で "なぜ" | 180超は A社で引受不可 |
| H | 対応(追加確認 / 代替候補社) | 要確認→追加確認項目 / NG→他社の代替案 | 代替: B社医療で要確認扱いなら通る可能性 |
| I | 情報源 | A社研修§/営業担当メール/先輩口伝/過去申込 | A社研修 v2024 §3.2 / A社営業チャット 2024/06 |
| J | 最終更新 | 日付 + 更新者 | 2026-07-14 田中 |

### 代理店視点だからこその設計ポイント

- **1行 = 1 (条件 × 保険会社 × 商品ジャンル)** で書く。同じ条件でも会社が違えば **別の行**。
  → 例: 「高血圧180超」を A社行(NG)と B社行(要確認)の2行に分ける
- **H列(対応)** に、NG時の "この会社なら通るかも" を書く。これが代理店の付加価値。
- **I列(情報源)** に「A社営業(田中さん)チャット」「先輩口伝」「過去申込 佐藤様案件」など、
  聞いた相手ごとに記録 → **各社の情報の鮮度が保てる**。
- **C列(保険会社)** は 会社名の色分けで、視覚的に "A社行" "B社行" を区別可能。

## セットアップ手順 (講師デモ用: 20分)

### 1. スプシの取り込み

1. `引受判定マスタ_テンプレ.xlsx` を Google ドライブへアップロード

### 2. デモナレッジの共有

- 演習2: 「以下のマスタ表(CSV)から、顧客に対して "どの会社の商品が通りそうか" を判定して」

## 動作確認 (20分)

### A. マスタ表への統合(演習1 の確認)

1. デモナレッジ01(口伝メモ)から「妊娠中の医療は B社が告知項目なしで通る」を抽出
2. デモナレッジ02(B社チャット 2024/07/18)にも同じ内容 → **1行に統合**、情報源列に両方書く
3. 記入例シートの `RULE-007` と一致することを確認

### B. AI 一次判定(演習2 の確認)

1. マスタ表を CSV でコピー
2. Gemini に貼り付け:

```
あなたは保険代理店の「事前引受スクリーニング AI」です。
以下は うちの代理店が扱う各社の引受判定マスタ表(CSV)です。
[CSV貼付]

これをルールとして、次の顧客について「どの会社の どの商品なら通りそうか」を判定してください。

顧客: 45歳男性 / 高血圧治療中(1年経過、収縮期185mmHg) / 医療保険希望

出力形式:
- 検討した条件: (どの条件詳細に該当するか)
- 通りそうな会社(YES): 会社名 + 商品ジャンル + 条件ID
- 要確認で相談推奨: 会社名 + 商品ジャンル + 条件ID + どんな追加確認が必要か
- 引受不可(NG): 会社名 + 商品ジャンル + 条件ID
- 代替提案: (該当がない場合、緩和型など次の一手)
- 次のアクション: どの会社の営業担当に事前相談すべきか

該当ルールがない場合は「該当なし → 各社支社に事前相談要」と返してください。
最終判定は各保険会社が行います。
```

3. Gemini の出力に「参照した条件ID」が入っていること、「A社NG / B社要確認」のような **会社別の見立て** が出ることを確認

### C. 該当なしフォールバックの確認

- マスタにない条件を渡す:
  「顧客: 30歳男性 / パラグライダー競技選手 / 死亡保険」
- 「該当なし → 各社支社に事前相談要」と返ることを確認(勝手に "YES" と出さないこと)

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| ナレッジから条件が抽出できない | Gemini に「以下から引受判定条件を抽出して代理店マスタ表(10列)にして」と依頼、素材ごと丸投げでOK |
| 同じ条件で複数会社の判定が混ざる | 「同じ条件でも会社が違えば 別の行 に分けて」と明示的にプロンプトに書く |
| Gemini が「該当なし = YES」で返す | プロンプトに「該当なし = 各社支社に事前相談要」と明示的に書く |
| マスタ表が長すぎて Gemini に貼れない | カテゴリ別 or 会社別に分割、または CSV ファイルとして添付 |
| 各社パンフを更新するたびに手作業がしんどい | パンフ改訂を掴んだら まず「更新ログ」に書き込み、月次見直しでマスタに反映する運用に |

## 継続運用のコツ

- **月1回15分の見直し会議**: 更新ログを見返し、各社の商品改定情報を追加・修正・無効化
- **「口伝」の正式化**: 情報源列に "口伝" と書かれた行を、月1件でも各社の営業担当に確認して正式化
- **過去申込結果メモ の活用**: 実際に断られた / 通った案件を「過去申込結果メモ」に残し、マスタ表の "情報源" にも紐付ける
- **削除より無効化**: 商品廃止になっても行は残す(過去顧客への説明時に必要)、"有効/無効" 列を追加で対応
- **各社の営業担当リスト**: マスタ表とは別に「各社の支社担当リスト」も持つと、要確認時のエスカレーションが素早くなる
