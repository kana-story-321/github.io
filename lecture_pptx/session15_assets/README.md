# 第15回 デモ資材 — 代理店の "商品別 引受判定" マスタ表

## 想定シチュエーション

**保険代理店** として複数社の保険商品を扱っている。
お客様が「A社医療プレミアムに入りたい」と言ってきた → 申込 → **謝絶** される。
「せっかく申込書書いたのに落ちた」という残念な体験を減らしたい。

**そのため**、扱っている **商品ごと** に引受条件を代理店内でメモしておき、
AI に「この顧客が この商品 に申し込む場合、通るか?」を **申込前** に判定させたい。

## 「引受判定マスタ表」の列設計 (10列 / 商品軸)

| 列 | 名前 | 説明 | 記入例 |
|---|---|---|---|
| A | 条件ID | `RULE-001` などの一意ID(削除より "無効化" 推奨) | RULE-004 |
| B | 保険会社 | どの会社の商品か(会社別に色分け) | A社生命 |
| C | **商品名** | 具体的な商品名(医療プレミアム / 医療スタンダード など) | 医療プレミアム |
| D | カテゴリ | 年齢 / 健康 / 職業 / 既往歴 / 金額 / その他 | 健康 |
| E | 条件詳細 | 顧客の状態を自然言語で具体的に | 高血圧 180超 |
| F | **この商品での判定** | YES / YES(条件付) / 要確認 / NO | NO |
| G | 判定理由 | 1〜2文で "なぜ" | 180超は 医療プレミアムで引受不可 |
| H | 対応(追加確認 / NG時の代替商品や再申込タイミング) | 顧客に伝える対応 | 代替: D社医療ライト(緩和型)を検討 or 血圧安定後に再申込 |
| I | 情報源 | 商品パンフ/研修§/営業担当メール/先輩口伝/過去謝絶案件 | A社研修資料 v2024 §3.2 / A社営業田中さん 2024/06 |
| J | 最終更新 | 日付 + 更新者 | 2026-07-14 田中 |

### この設計の意味

- **1行 = 1つの引受条件(商品 × カテゴリ × 条件)** で書く。
  同じ条件でも 商品が違えば 別々の行 に(例: 「妊娠12週未満」 → A社医療プレミアムはNG行、B社医療スタンダードはYES行)。
- **C列(商品名)** でソート/フィルタすると「この商品の条件一覧」がすぐ見える → **商品カルテ** として使える。
- **H列(対応)** に、NG時に "どう対応するか"(別商品を勧める / 再申込タイミング / 顧客への説明) を書く。
- **I列(情報源)** に「誰から聞いた / どの資料か」を書き残す。**"口伝(要正式化)" もそのまま書く** → 後で商品担当に確認する目印。

## セットアップ手順 (講師デモ用: 20分)

### 1. スプシの取り込み

1. `引受判定マスタ_テンプレ.xlsx` を Google ドライブへアップロード
2. 右クリック → 「Google スプレッドシートで開く」
3. 3シート (引受判定マスタ / 引受判定マスタ_記入例 / 更新ログ) を確認

### 2. デモナレッジの共有

- 6ファイル(md 5件 + xlsx 1件)を Google ドライブの共有フォルダにアップ
- 生徒に "読める状態" で配布

### 3. Gemini 側の準備

- Gemini(Google AI Studio or Gemini アプリ)にログイン済み状態
- 演習1 の途中: 「以下のメモから 商品ごとの引受条件を抽出して 10列のマスタ表(JSON)に整理して」
- 演習2: 「以下のマスタ表(CSV)から、この顧客がこの商品に申し込んだら通るかを判定して」

## 動作確認 (20分)

### A. マスタ表への統合(演習1 の確認)

1. デモナレッジ01(口伝メモ)の「A社医療プレミアムは高血圧180超NG」を抽出 → マスタ表に1行(RULE-004)
2. デモナレッジ03(A社研修)にも同じ内容 → **1行に統合**、情報源列に両方書く
3. 記入例シートの `RULE-004` と一致することを確認

### B. AI 一次判定(演習2 の確認)

1. マスタ表を CSV でコピー
2. Gemini に貼り付け:

```
あなたは保険代理店の「引受判定サポートAI」です。
以下は うちの代理店が扱う各商品の引受判定マスタ表(CSV)です。
[CSV貼付]

これをルールとして、次の顧客が指定した商品に申し込む場合、通るかを判定してください。

顧客: 45歳男性 / 高血圧治療中(1年経過、収縮期185mmHg)
検討中の商品: A社医療プレミアム

出力形式:
- この商品での判定: YES / 要確認 / NO
- 該当した条件ID: RULE-XXX
- 判定理由: 1〜2文
- 対応(NG時の再申込タイミング / 代替商品案内 / 追加確認事項):
- 次のアクション: 誰に確認するか、何を伝えるか

該当ルールがない場合は「該当なし → 商品担当に事前確認要」と返してください。
最終判定は保険会社が行います。
```

3. Gemini の出力に「該当した条件ID」が入っていること、**この顧客とこの商品の組合せに絞った判定** が返ることを確認

### C. 別商品での再判定

- 同じ顧客で商品だけ変えて再判定:
  「顧客: 45歳男性 / 高血圧185mmHg / 検討中の商品: **D社医療ライト**」
- 「D社医療ライトなら3項目告知に該当しなければYES」のような 別商品での判定 が返ることを確認

### D. 該当なしフォールバック

- マスタにない条件を渡す:
  「顧客: 30歳男性 / パラグライダー競技選手 / 検討中の商品: A社死亡プレミアム」
- 「該当なし → 商品担当に事前確認要」と返ることを確認(勝手に "YES" と出さないこと)

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| ナレッジから条件が抽出できない | Gemini に「以下から引受条件を抽出して、商品名ごとに10列マスタ表(JSON)にして」と依頼、素材ごと丸投げでOK |
| 同じ条件が複数商品に登場する | 商品ごとに 別行 に分けて書く(1条件×1商品 = 1行) |
| Gemini が「該当なし = YES」で返す | プロンプトに「該当なし = 商品担当に事前確認要」と明示的に書く |
| マスタ表が長すぎて Gemini に貼れない | 検討商品でフィルタして、その商品ぶんだけ CSV で貼付 |
| 各商品パンフを更新するたびに手作業がしんどい | パンフ改訂を掴んだら まず「更新ログ」に書き込み、月次見直しでマスタに反映 |

## 継続運用のコツ

- **月1回15分の見直し会議**: 更新ログを見返し、各商品の改定情報を追加・修正・無効化
- **「口伝」の正式化**: 情報源列に "口伝" と書かれた行を、月1件でも商品担当に確認して正式化
- **過去謝絶案件メモ の活用**: 実際に断られた案件を「過去謝絶案件メモ」に残し、マスタ表の "情報源" にも紐付ける
- **削除より無効化**: 商品廃止になっても行は残す(過去顧客への説明時に必要)、"有効/無効" 列を追加で対応
- **商品追加時のテンプレ**: 新しい商品を扱い始めたら、その商品のパンフをGeminiに投げて「10列マスタ表の3〜5行を作って」と依頼 → 一気に商品カルテが増える
