# W3 デプロイ手順書 ─ 引受判定AI を "使える形" に

## デプロイ方法(W1で選んだ UI に応じて)

W1「3_UI設計」で選んだ画面によって、デプロイ手順が変わります。

| UI形式 | デプロイ方法 | 難易度 | 共有先 |
|---|---|---|---|
| **A: サイドバー** | スプシを共有するだけ | ★☆☆ | スプシへのアクセス権を持つ人 |
| **B: Webアプリ** | GAS の Webアプリとして公開 | ★★☆ | URL を知る誰でも / 社内限定 |
| **C: Googleフォーム** | フォームURLを配布 | ★☆☆ | URL を知る誰でも |

---

## パターン A: サイドバー版のデプロイ (5分)

### 1. スプシの共有権限を設定
1. 引受判定マスタスプシ 右上「共有」ボタン
2. 「一般的なアクセス」を "リンクを知っている全員" or 特定ユーザーに設定
3. 権限: **編集者** (実行時にスプシ書き込みが要るため)

### 2. 若手全員に配布
- スプシURL を Slack / メール / 社内Wiki で共有
- 各ユーザーがスプシを開く → メニュー「引受判定」表示
- 初回のみ 各ユーザーで 権限承認 が必要

### 3. 動作確認
- 別アカウントでスプシを開き、メニュー「引受判定」が出るか確認
- 「▶ 判定ツールを開く」でテスト

---

## パターン B: Webアプリ版のデプロイ (10分)

### 1. GAS プロジェクトに Web App 追加コードを貼付
1. 既存の Code_引受判定.gs はそのまま
2. 左の＋アイコン → 「スクリプト」→ 新規追加
3. Web アプリ用の doGet 関数を追加(講師配布のサンプルコード参照)
4. HTMLファイル「WebApp」を追加、UI を貼付
5. 保存

### 2. Webアプリとしてデプロイ
1. GASエディタ右上「デプロイ」→「新しいデプロイ」
2. 種類の選択(歯車アイコン) → **「ウェブアプリ」**
3. 設定:
   - 説明: `引受判定AI v1.0`
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **Workspace内 全員**(顧客情報を扱うため)
4. 「デプロイ」ボタン
5. **アクセス権を承認**(初回のみ)
6. 発行された **Webアプリの URL** をコピー

### 3. URL を配布
- Slack / メール / 社内Wiki で URL を共有
- 各ユーザーは URL を開くだけで使える(スプシを開かなくてOK)

### 4. 動作確認
- 別ブラウザ(シークレットモード)で URL を開く
- 判定フォームが表示される → 動作テスト

### 5. 更新の反映
- コードを修正したら、「デプロイ」→「デプロイを管理」→ 既存デプロイの ✏編集 → 「バージョン」を "新しいバージョン" に → 「デプロイ」
- 毎回 "新しいデプロイ" にすると URLが変わるので注意

## パターン C: Googleフォーム版のデプロイ (5分)

### 1. Googleフォームで入力フォーム作成
顧客情報 と 検討商品 を選択形式で:
- 顧客名(仮名OK) — 短文回答
- 年齢 — 数値
- 性別 — 選択
- 健康状態 — 段落(自由記述)
- 職業 — 短文回答
- 既往歴 — 段落
- 検討商品 — 選択(A社医療プレミアム / A社死亡プレミアム / … の一覧)

### 2. フォーム回答時のトリガー設定
1. GAS プロジェクトで `onFormSubmit(e)` 関数を追加
2. トリガー設定: GASエディタ「トリガー」→ 「+」→ イベントの種類: **フォームから送信時** → 関数: `onFormSubmit`
3. 権限承認

### 3. フォームURL を配布
- 「フォームを送信」→ URLコピー
- 若手営業などに配布、記入すると自動で判定実行 → 結果は指定メールへ通知

## デプロイ時の 注意事項

### セキュリティ
- **API キー漏洩防止**: スクリプトプロパティ経由を厳守
- **アクセス範囲**: 顧客情報を扱うので、「全員(限定なし)」は避ける → Workspace限定 or 特定メールアドレス許可
- **顧客情報の匿名化**: テスト時は絶対に実顧客名を入れない

### 権限
- Webアプリ版で「次のユーザーとして実行」を **自分** にすると:
  - 他ユーザーの実行時も API 呼び出しが自分の権限で動く
  - Gemini API の従量課金も自分に来る(無料枠内に注意)

### バージョン管理
- 変更のたびに 「デプロイ管理」→ 既存デプロイの編集 → "新しいバージョン" を選択
- 「新しいデプロイ」で毎回作ると URL が増えて管理不能に

### 監査ログ
- 「判定履歴」シートに 実行日時+顧客ID+実行者 を追記する運用推奨
- 個人情報保護の観点で "誰がいつ何を判定したか" 追える状態に

## デプロイ後の運用ルール(演習2で決めること)

### 1. 誰が使う?
- 若手営業(1-3年目)中心 / ベテランは月次ノウハウ追加担当

### 2. AI 判定をどう扱う?
- **AI 判定は "参考"、最終決定は 保険会社**
- 該当条件ID を必ず確認(なぜこの判定?の根拠)
- 該当なしの場合は 商品担当に事前確認

### 3. 独自ルール更新は誰が?
- 担当ベテラン(月1回、5-10分)で追加
- 過去謝絶案件を月次でレビュー、独自ルール化

### 4. 個人情報の扱い
- 質問には 顧客名・電話番号を含めない
- 「45歳男性 高血圧180超」等の 属性表現で
- 判定履歴の閲覧権限を絞る

### 5. 顧客への活かし方
- 「AI 判定によると…」と言わない、代理店の説明として自分の言葉で
- 判定NG時は 代替商品を必ず提示、"申込前に別ルート提案"

## トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| Webアプリ URL を開いても白画面 | 権限承認未完了 | GASエディタで `doGet` を実行、権限承認 |
| 「このアプリは Google で確認されていません」 | 通常表示、実害なし | 「詳細」→「安全ではないページに移動」 |
| 別ユーザーで実行できない | アクセス権限が「自分」 | デプロイ管理で アクセスユーザーを変更 |
| コード変更が反映されない | 再デプロイ忘れ | 「デプロイ管理」→ 編集 → 新しいバージョン |
| API エラー(429) | 無料枠のレート制限 | 1-2分待ってリトライ |

## 発展課題

1. **通知連携**: NG判定時に 担当マネージャーに Slack通知
2. **一括判定**: 顧客リスト(スプシ10行)を一括判定
3. **顧客向けPDF**: 判定結果を PDF化 → 顧客へメール送信
4. **他システム連携**: 保険会社の申込システムと直接連携
5. **判定履歴分析**: 半年分の履歴から "よく発火する条件" を発見→ルール強化
