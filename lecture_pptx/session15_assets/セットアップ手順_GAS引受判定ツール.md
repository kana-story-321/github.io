# 第15回 W02 引受判定ツール セットアップ手順 (GAS)

## 完成イメージ

- 代理店が普段使う **引受判定マスタ.スプシ** を開く
- メニュー「引受判定」→「判定ツールを開く」で サイドバー起動
- 顧客情報 + 検討商品 を入れて「判定する」ボタン
- Gemini が マスタ表を読んで判定 → サイドバーに結果表示
- 同じスプシの「判定履歴」シートに全件自動保存

---

## 事前準備 (15分)

### 1. Gemini API キーを取得

1. [Google AI Studio](https://aistudio.google.com/apikey) にログイン
2. 「Create API key」→ 新しいプロジェクトを選択
3. 表示された `AIzaSy...` で始まる文字列を **メモ帳に一時保存**

> ⚠️ このキーは鍵と同じ。他人と共有しない、SNS に貼らない、コードに直書きしない。

### 2. スプシと GAS プロジェクトの準備

1. `ワーク01完成_引受判定マスタ.xlsx`(ワーク01の成果物)を Google ドライブへアップロード
2. 右クリック →「Google スプレッドシートで開く」
3. シート名が **「引受判定マスタ」** であることを確認(GAS がこの名前で読む)
4. メニュー「拡張機能」→「Apps Script」で エディタを開く

### 3. コードを貼り付け

1. デフォルトの `Code.gs` を全消し → **`Code_引受判定.gs` の中身を貼付**
2. 左の＋アイコン → 「HTML」→ ファイル名 **`Sidebar`** で新規追加
3. `Sidebar.html` の中身を貼付
4. 保存(Ctrl+S / Cmd+S)

### 4. Gemini API キーをスクリプトプロパティに登録

1. GAS エディタ左サイドバー「⚙ プロジェクトの設定」
2. 下にスクロール → 「スクリプト プロパティ」→「スクリプト プロパティを追加」

| プロパティ | 値 |
|---|---|
| `GEMINI_API_KEY` | (メモしておいた AIzaSy... の文字列) |

3. 「スクリプトプロパティを保存」

### 5. 初回動作確認

1. GAS エディタで **関数選択ドロップダウン** から `testSetup` を選び「実行」
2. 初回は権限承認画面 → 「詳細」→「安全ではないページに移動」→「許可」
3. 実行ログ(下部)に以下が出れば成功:
   ```
   GEMINI_API_KEY: AIzaSy...(OK)
   マスタ表 行数: 25
   商品リスト:
     A社生命 / 医療プレミアム
     A社生命 死亡プレミアム
     ...
   ```

### 6. スプシに戻ってメニュー確認

1. スプシのタブに戻り、**再読み込み(F5)**
2. メニューバーに **「引受判定」** が表示されることを確認
3. 「引受判定」→「判定ツールを開く」→ サイドバー表示

## 動作テスト (10分)

### ケース1: 45歳男性 / 高血圧185mmHg / A社医療プレミアム
サイドバーに以下を入力して「判定する」

- 年齢: `45`
- 性別: `男`
- 健康状態: `高血圧治療中(1年経過、収縮期185mmHg)`
- 職業: `会社員`
- 検討中の商品: `A社生命 / 医療プレミアム`

**期待結果**:
- 判定: **NO** (赤バッジ)
- 該当条件ID: `RULE-004`
- 判定理由: 収縮期185mmHgは「高血圧180超」に該当し、A社医療プレミアムでは引受不可
- 対応: 代替として D社医療ライトを検討 or 血圧安定後に再申込

### ケース2: 同じ顧客 × D社医療ライト (緩和型)
「検討中の商品」だけ `D社生命 / 医療ライト(緩和型)` に変更して再判定

**期待結果**:
- 判定: **YES** (緑バッジ)
- 該当条件ID: `RULE-023`
- 商品を切り替えたら別のルールが発火することを確認

### ケース3: 該当なしテスト
- 年齢: `33`
- 健康状態: (空)
- 職業: `プロサッカー選手`
- 検討中の商品: `A社生命 / 死亡プレミアム`

**期待結果**:
- 判定: **該当なし** (グレーバッジ)
- 該当条件ID: `該当なし`
- 「マスタ表に該当ルールなし → 商品担当に事前確認要」

→ AI が勝手にYESと判定しないことを確認(**安全弁**)

### 判定履歴シートの確認
- スプシに戻り「判定履歴」シートを開く
- 上記3件の判定が全て記録されていることを確認

## 動作しないとき (トラブルシューティング)

| 症状 | 原因と対処 |
|---|---|
| サイドバーが「読み込み中...」のまま | GAS の実行権限を承認していない。GAS エディタで `testSetup` を1度実行して権限承認 |
| 「GEMINI_API_KEY が未設定」 | スクリプトプロパティに正しく登録できていない。プロパティ名は完全一致(スペース禁止) |
| 「Gemini API エラー (429)」 | 無料枠のレート制限。1分待ってリトライ |
| 「Gemini API エラー (403)」 | APIキーが無効 or 課金設定されていないプロジェクトのキー。Google AI Studio でキー再発行 |
| 「シート「引受判定マスタ」が見つかりません」 | マスタ表のシート名を「引受判定マスタ」に統一。Code 冒頭の `MASTER_SHEET` 定数と一致させる |
| 判定が全部「該当なし」になる | プロンプトが弱い。マスタ表の条件詳細列(E列)を具体化 or Code_引受判定.gs の `buildPrompt_` を強化 |
| メニュー「引受判定」が出ない | スプシを再読み込み(F5)。それでも出ないなら GAS エディタで `onOpen` を手動実行 |

## 運用のコツ (演習2 の後半)

- **判定履歴を月1回レビュー**: どの商品で "該当なし" が多発したら、その商品のルール追加を検討
- **精度検証**: 過去の "実際に謝絶された案件" 20件を投入 → AI 判定が一致するかで精度測定(目標 85%以上)
- **担当者ごとの権限**: スプシの共有権限で 若手=閲覧のみ / ベテラン=編集可 のように運用
- **マスタ表更新後のキャッシュ問題なし**: GAS は毎回 `readMasterTable_` でスプシから読むため、マスタ表を編集したら即反映

## 応用: 発展課題

1. **判定結果を LINE に送信**: 顧客から LINE で問い合わせ → GAS → Gemini 判定 → LINE 返信(第11回 W02 の応用)
2. **一括判定**: 顧客リスト(スプシに10行)を一括判定 → 全件を判定履歴に保存
3. **PDF レポート**: 判定結果を PDF 化して顧客説明用に(GAS の DocumentApp 使用)
4. **Slack 通知**: 「NG」判定が出たら Slack に自動投稿 → チームで代替商品を即議論
