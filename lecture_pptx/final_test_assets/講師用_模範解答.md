# 研修最終まとめテスト 模範解答 (講師用)

## 使い方

- Part 3(Q&A タイム)で 順に読み上げながら答え合わせ
- 生徒の回答が異なっても "考え方が合っていれば OK" として拾う
- 完全な正解より、"なぜそう答えたか" を確認する
- ここに載っていない良い視点が出たら、その場で称賛+共有

---

## Part 1: ツール別テスト (15問)

### ① Gemini (対話AI)

**G-1: プロンプトの精度を上げる「4つの要素」**
- **役割**(あなたは〇〇です)
- **目的**(何をしてほしいか)
- **制約**(文字数、トーン、避けるべき内容)
- **出力形式**(箇条書き、表、JSONなど)
→ この4つを揃えると精度が大きく上がる

**G-2: 提案文を書かせる時、必ず伝える3つ**
- お客様のプロフィール(年齢/家族構成/職業など)
- 提案する保険商品の情報(商品名/特徴/条件)
- お客様の悩み・目的(老後不安/教育資金/保障見直しなど)
+ ボーナス: トーン(丁寧/親しみやすい)、文字数

**G-3: 同じ質問で毎回違う答えの対処**
- 期待する出力例(Few-shot)を最初に見せる
- 具体的な制約を追加(「200字以内で」「箇条書き3項目で」など)
- 「temperature を下げる」相当の指示(「保守的に」「事実ベースで」)
- 出力形式を JSON など固定形式に指定

### ② NotebookLM (資料AI)

**N-1: Gemini との一番の違い**
- Gemini はインターネット全体+学習データから回答
- **NotebookLM は自分がアップした資料"だけ"から回答**
- → 出典が明確、社内情報を安全に使える、ハルシネーション(嘘の情報)が起きにくい

**N-2: 出典明示のメリット (2つ以上)**
- 顧客/上司への説明時に「この情報はここに書いてある」と根拠を示せる
- 誤った情報が返っても "元資料が古い" と原因追跡できる
- コンプライアンス上、"どこからの情報" が追える
- 社内マニュアルの検索効率が上がる(ページ番号まで教えてくれる)

**N-3: 社内マニュアル100ページから FAQ 作成**
1. NotebookLM に PDF をアップロード(ソースとして登録)
2. 「よくある質問を10個、社内マニュアルの内容から抽出してください」と依頼
3. 回答を確認、出典ページを見て 追加の質問「〇〇について詳しく」等で深掘り
4. FAQ集としてスプシに整理

### ③ Genspark (調査AI)

**S-1: Google検索との違い(一言)**
- 「Google=検索結果を返す、Genspark=検索結果を統合したレポートを返す」
- または: 「Google=リンクの一覧、Genspark=まとまった答え+出典」

**S-2: 出典付きが重要な理由**
- 業務資料に引用する時、出典が必須(信頼性・コンプラ)
- お客様説明時に「◯◯調査ではこう」と根拠を示せる
- AI の "ハルシネーション" を出典で検証できる
- 情報源の信頼性(公的機関/新聞/個人ブログ)を判断できる

**S-3: 「保険業界 2026年上半期の動向」を調べる**
- Deep Research 機能を使う
- プロンプト: 「保険業界の 2026年上半期(1月〜6月)の動向を、法改正・新商品・市場データ・M&A の観点で調べてください。日本国内中心で、公的機関・大手新聞・業界誌を優先ソースに」
- 返ってきたレポートを 出典付きで確認、必要なら追加質問

### ④ Canva (デザインAI)

**C-1: Canvaの業務用途 (3つ)**
- お客様配布用の月次レポート・チラシ
- 社内研修資料・プレゼン
- SNS投稿画像(Instagram・Facebook)
- 名刺・商品パンフレット
- 動画コンテンツ

**C-2: Magic Design の使い方**
1. Canva トップページで「Magic Design」or「デザインを作成」
2. 作りたい内容をテキストで入力(例: 「保険相談会のチラシ、20代女性向け」)
3. AI が複数のデザイン案を生成
4. 気に入ったものを選んで編集(色・文言・画像差し替え)
5. ダウンロード or 共有

**C-3: 月次レポート表紙で意識すること**
- 会社のブランドカラー・ロゴを反映(ブランドキット活用)
- 顧客の名前・年月を明記
- 情報量を絞る(表紙は "パッと見て何のレポートか" 分かる程度)
- 硬すぎず、親しみやすい配色
- 顧客層に合わせた雰囲気(若い→カラフル、シニア→落ち着いた色)

### ⑤ GAS (自動化ツール)

**GAS-1: コードを書く前にすること**
- **業務フロー棚卸し**(誰が/何を/何分/どのツールで)
- 「手動 / 半自動 / 自動」で色分け
- 「AI に任せられそう」を発見
- **設計書を作る**(DB設計・判断基準・UI・独自ルール)
- → いきなり書き始めない、これが最重要

**GAS-2: APIキーの保存場所と理由**
- **スクリプトプロパティ** に保存する
- 理由:
  - コードに直書きすると GitHub 等に上げた時に漏洩
  - 別ユーザーが GAS を見ても API キーが見えない
  - キーの入れ替えが コード修正なしでできる

**GAS-3: チーム展開の2種類**
- **サイドバー版**: スプシを共有するだけ(編集者権限を Workspace 内に)
- **Webアプリ版**: GAS を "ウェブアプリ" としてデプロイ → URL 発行 → 別ブラウザで使える
+ (フォーム版): Google フォーム配布 + onFormSubmit トリガー

## Part 2-1: GAS 応用テスト

**GAS-A1: 3つのAI に共通する "設計の考え方"**
- **入力(スプシ) → AI(Gemini)で処理 → 出力(スプシ/Docs)** の流れ
- 「顧客ごとの情報」と「全員共通の前提」を別シートに分ける
- 独自の判断ルールは スプシで管理(コードに直書きしない)
- AI 出力は必ず "型(JSON構造)" で受け取る
- 承認・確認は必ず人がやる(AI が最終決定しない)

**GAS-A2: 顧客情報 と 共通前提を別シートに分ける理由**
- **更新頻度が違う**(顧客情報=毎回変わる、共通前提=年1回見直し)
- 混在させると 顧客ごとに前提を書き直すハメになる → 更新運用が回らない
- 別シートなら 共通前提の変更が 全顧客に自動反映される
- 「これは誰がいつ更新?」の責任分担が明確になる

**GAS-A3: 独自ルールはコード? スプシ?**
- **スプシに書くべき**
- 理由:
  - スプシなら 現場が自分で追加・修正できる(コード変更 = 開発者呼ぶ)
  - GAS はスプシからルールを読むだけ、コード変更なし
  - 更新履歴がスプシで追える
  - 月1回のルール追加が 現実的な運用として回る
- コードに書くと: 変更のたびに開発者呼ぶ → 更新が滞る → 使われなくなる

**GAS-A4: "勝手にYES と言わせない" プロンプト指示**
- 「該当ルールがない場合は "該当なし" と返してください」を明記
- 「該当なし → 人が判定(担当者に確認)」とフォールバック指示
- 「AI が勝手に推測して回答してはいけない」を明示
- responseSchema で verdict の enum に "該当なし" を含める

**GAS-A5: 運用ルールを決める重要性**
- 決めないと "誰も更新しない放置ツール" に(3ヶ月で使われなくなる)
- 誰が使う → 権限管理、教育計画
- いつ更新 → 情報の鮮度維持
- 何をチェック → 品質担保
- → 決めないと "動くだけの実験ツール" 止まり、業務改善につながらない

## Part 2-2: 総合シナリオ

### シナリオ ①: 新入社員向けQ&Aボット

**Q1: どのツールを使う?**
- **NotebookLM** が最適
- 理由: 社内資料を根拠に回答してくれる、出典明示でエビデンス確認可
- 補助: LINE公式アカウント+GAS で若手が LINE で質問→NotebookLM経由で回答返信

**Q2: 社内マニュアル100ページを根拠にする組み合わせ**
- NotebookLM に 社内マニュアルPDFをアップロード
- 若手からの質問を GAS が受ける → NotebookLM API(なければ手動) → 回答返信
- または NotebookLM のシェア機能で 若手全員に アクセス権付与

**Q3: エスカレーション設計**
- NotebookLM が「該当情報なし」or 信頼度低い時は "ベテランに転送" フラグ
- Slack / メールで担当ベテランに通知(GAS で自動化)
- ベテランの回答は NotebookLM のソース資料に追記 → 次回から AI が答えられる
- → 継続的に AI の回答範囲が広がる仕組み

### シナリオ ②: 月次営業レポート自動化

**Q1: データ収集の効率化**
- **Google フォーム** + **GAS** (フォーム回答 → スプシに自動集計)
- 各営業がスマホでも入力可、月末最終日に自動リマインダー
- または既存Excel からのインポートを GAS で自動化

**Q2: 集計+洞察コメントの自動化**
- スプシで自動集計(SUMIF等の関数)
- **Gemini** に「今月の営業データから 3つの洞察と 来月への提案を書いて」と依頼
- GAS で スプシデータ → Gemini プロンプト → 洞察テキスト をDocs に書き出し
- → 半日の集計+コメント作業が 数分に

**Q3: "経営陣が読みたくなる見た目"**
- **Canva** でテンプレート化(月次レポート用のブランドキット)
- 数値はグラフ化(GAS でグラフ自動生成、Canva に画像貼付)
- 表紙・目次・グラフ・洞察 の順に構成
- 前月比・目標達成率 を色分けで可視化
- 3ページ程度に凝縮、読みやすさ最優先

## 要点まとめ (6つ) — 生徒に持ち帰ってほしい

1. **AI は "万能" ではない** → 各ツールに得意分野、シーンで使い分け
2. **設計 → 実装 の順** → いきなり作らず、まず何を作るか言語化
3. **人 / AI / GAS の分担** → 責任は人、情報整形はAI、繰り返しはGAS
4. **更新しやすい構造で作る** → 顧客情報と共通前提を分離、独自ルールはスプシ
5. **AI 出力は必ず 人が確認** → "AI がやってくれる" ではなく "AI と一緒にやる"
6. **動かして 使いながら 育てる** → 完璧を目指さない、月次で少しずつ改善

## Q&A タイム の進め方

1. **答え合わせを1問ずつ丁寧に**(15問で 20-25分)
2. **総合シナリオは グループディスカッション形式**(10分)
3. **各自の "持ち帰りメモ" を発表**(5-10分)
4. **講師への自由質問** (10-15分)

各生徒に "今日から始める1つ" を宣言してもらって締め。
