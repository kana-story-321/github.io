# 🔧 チャットが動かない時の直し方

**症状**: doGet は成功しているのに、質問を送っても何も返ってこない/エラーが出る。

---

## 🎯 まず原因はこれ (今回の修正で解決済み)

**GAS で HtmlService が返す HTML は、Google のサンドボックス iframe（`googleusercontent.com`）で動きます。**
そのため、HTML の中から `fetch('?q=...')` で自分の GAS の doGet を呼ぼうとしても、**そもそもリクエストが飛びません**（サンドボックスの外に出られない）。

### ✅ 直し方 = `google.script.run` を使う

**GAS 公式の「HTML → 関数直接呼び出し」の仕組み**を使います。今回配布した **修正版 `Code.gs` と `Index.html`** はこれに書き換え済みです。

---

## 🚀 修正版の適用手順（3分）

### 1. Code.gs を **修正版** で置き換え

- GAS エディタで `Code.gs` を開く
- 中身を全部消して、**新しい `Code.gs`**（同梱の最新版）を貼り付け
- **保存**（Ctrl+S）

### 2. Index.html を **修正版** で置き換え

- 左のファイルツリーで `Index` (HTMLファイル) を開く
- 中身を全部消して、**新しい `Index.html`** を貼り付け
- **保存**

### 3. デプロイし直す（**とても重要**）

GAS はコードを保存しただけでは Web アプリに反映されません。**新しいバージョン**でデプロイし直します。

1. 右上「**デプロイ**」→「**デプロイを管理**」
2. アクティブなデプロイの右上の **鉛筆マーク（編集）**
3. 「バージョン」を「**新しいバージョン**」に切り替え
4. 説明: 「google.script.run 対応」
5. 「**デプロイ**」

> 💡 **新しい URL は出ません**（同じ URL のまま最新版が動きます）。既存のリッチメニュー設定はそのままで OK。

### 4. 動作確認

1. スマホ or PCブラウザでウェブアプリ URL を開く
2. 右上の **「🔧 診断」ボタン**をタップ
3. 「サーバOK / FAQ: 10件 / APIキー: あり / モデル: gemini-2.5-flash」と出れば正常
4. 質問を入れて送信 → 応答が返るはず

---

## 🩺 それでも動かない場合のチェックリスト

以下を **上から順に** 確認してください。

### ① 診断ボタンの結果は？

| 結果 | 意味 | 対処 |
|---|---|---|
| `サーバOK / FAQ: 10件 / APIキー: あり` | 完璧 | 質問して応答を確認 |
| `FAQ: 0件` | シート読めていない | 下の②へ |
| `APIキー: なし` | スクリプトプロパティ未設定 | 下の③へ |
| `接続エラー` | ウェブアプリ URL が古い or 権限問題 | 下の④へ |

### ② FAQ シートが読めない (FAQ: 0件)

- スプレッドシートの**シート名が正確に「FAQ」**か？（全角/半角、空白なし）
- 1行目の見出しが **A1:「質問」 B1:「回答」 C1:「カテゴリ」** になっているか？
- 2行目以降にデータが入っているか？
- **GAS プロジェクトが正しいスプレッドシートに紐付いている**か？
  （拡張機能 → Apps Script で開き直すと確実）

### ③ API キーが読めない (APIキー: なし)

- GAS エディタの左メニュー「⚙ **プロジェクトの設定**」
- 下の「**スクリプト プロパティ**」に **`GEMINI_API_KEY`** があるか？
- 値が `AIzaSy...` で始まる文字列になっているか？
- **保存ボタンを押したか？**（設定→保存を忘れると反映されない）

### ④ 接続エラー (google.script.run が使えない など)

- **開いている URL が正しいか？**
  - ウェブアプリのデプロイURL は `https://script.google.com/macros/s/xxxxx/exec` の形
  - もし `https://script.googleusercontent.com/...` を直接ブックマークしていたら NG
- **デプロイの権限設定**
  - デプロイ → デプロイを管理 → 編集
  - 「実行するユーザー: 自分」「アクセスできるユーザー: **全員**」を確認
- **ブラウザキャッシュ**
  - Ctrl + Shift + R でスーパーリロード

### ⑤ Gemini API エラー (HTTP 4xx)

- GAS エディタで **`verifyModel`** 関数を実行 → ログを確認
  - `✅ gemini-2.5-flash は利用可能` → API キーOK、モデルOK
  - `❌ ...は利用不可` → 別のモデル名に切り替え（後述）
  - `HTTP 400/403` → API キーが無効または未有効化

#### モデル名を変える場合

`Code.gs` の以下の行を変更:

```javascript
const MODEL_ID = 'gemini-2.5-flash';
```

**候補**（動作しない場合の代替）:
- `gemini-2.5-flash` （2026/07 GA・推奨）
- `gemini-2.0-flash`
- `gemini-1.5-flash`

変更後は **必ずデプロイし直し**。

## 🧪 GAS エディタから直接テストする（一番確実）

サーバ側の関数が動くかを、HTML を経由せず直接確認する方法:

1. GAS エディタで関数プルダウンから **`testAnswer`** を選択
2. 「▶ 実行」
3. **表示 → ログ** で結果確認

```
{
  "text": "はい、初回のご相談は無料です。オンライン(Zoom)または対面...",
  "handoff": false
}
```

こう出れば **サーバ側は完全に動作しています**。あとは HTML 側の問題だけ、ということが確定します。

---

## 📌 なぜ今回の不具合が起きたのか（技術背景）

Google Apps Script の Web アプリは、セキュリティのため HTML を **サンドボックス iframe** で提供します。この iframe は独自のドメイン（`googleusercontent.com`）で動作するため:

- ❌ `fetch('?q=xxx')` → 相対URL が iframe のドメイン内で解決 → GAS本体に届かない
- ❌ `fetch('https://script.google.com/macros/s/xxx/exec?q=yyy')` → CORS で弾かれる
- ✅ `google.script.run.関数名(引数)` → **GAS 公式の橋渡し API を通じて安全に呼べる**

これは GAS の仕様なので回避不可能。**HTML から GAS 関数を呼ぶときは必ず `google.script.run` を使う**、と覚えておいてください。

## 🎓 このバグから学べること

| 学び | 内容 |
|---|---|
| **AI コードは動作確認が必須** | Gemini が「動くコード」と言っても、環境固有のクセ(GAS iframe)は考慮しないことがある |
| **エラーメッセージは友達** | サイレントに失敗するのが一番怖い。診断ボタンやログ表示を最初から入れておく |
| **GAS ならまずは `testAnswer`** | HTMLを経由する前に「関数単体で動くか」を GAS エディタで確認するのが早い |
| **デプロイの再実行を忘れない** | コード保存 ≠ デプロイ更新。必ず「新しいバージョン」で再デプロイ |

これは **バイブコーディングのリアル**です。1回で完璧に動かないのが普通、直しながら育てるのが本番。
